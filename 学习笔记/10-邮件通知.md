## 一、邮件通知实现

### 1.1 为什么配置存 SystemParam 而不是 appsettings.json？

| 存储位置 | 优点 | 缺点 |
|---------|------|------|
| appsettings.json | 简单直接 | 修改需重启，不支持租户级覆盖 |
| SystemParam 表 | 运行时热更新，支持租户覆盖 | 需要先入库 |

**本项目选择 SystemParam 表**，因为这个系统本身就设计了多租户功能，每个租户可能使用不同的 SMTP 服务器。

## 二、核心实现

### 2.1 SmtpConfig 配置模型

```csharp
public class SmtpConfig
{
    public string Host { get; set; } = string.Empty;   // SMTP 服务器地址
    public int Port { get; set; } = 587;               // 端口，默认 587 (TLS)
    public string User { get; set; } = string.Empty;   // 发件邮箱账号
    public string Password { get; set; } = string.Empty; // 授权码（非登录密码）
    public string? From { get; set; }                  // 发件人显示地址，默认同 User
}
```

### 2.2 SmtpChannelProvider — 完整实现

```csharp
public class SmtpChannelProvider : IChannelProvider
{
    private readonly IServiceProvider _sp;
    private readonly ILogger<SmtpChannelProvider> _logger;
    public string Channel => "email";

    public SmtpChannelProvider(IServiceProvider sp, ILogger<SmtpChannelProvider> logger)
    {
        _sp = sp;
        _logger = logger;
    }

    public async Task SendAsync(string recipient, string title, string content, CancellationToken ct)
    {
        // ① 从 SystemParam 表读取 SMTP 配置（支持运行时热更新）
        var sysParam = _sp.GetRequiredService<ISystemParamService>();
        var json = await sysParam.GetValueAsync("smtp:default", ct);
        if (string.IsNullOrEmpty(json))
        {
            _logger.LogWarning("SMTP 未配置（SystemParam smtp:default 为空），跳过邮件发送");
            return;  // 未配置 → 静默跳过，不报错
        }

        // ② 反序列化 JSON 配置
        SmtpConfig? config;
        try { config = JsonSerializer.Deserialize<SmtpConfig>(json); }
        catch { _logger.LogError("SMTP 配置 JSON 格式错误"); return; }

        // ③ 验证必要字段
        if (config == null || string.IsNullOrEmpty(config.Host))
        {
            _logger.LogWarning("SMTP Host 为空，跳过邮件发送");
            return;
        }

        // ④ 发送邮件
        try
        {
            using var smtp = new SmtpClient(config.Host, config.Port);
            smtp.EnableSsl = true;
            smtp.Credentials = new NetworkCredential(config.User, config.Password);

            var from = config.From ?? config.User;  // 发件人默认用 User
            var mail = new MailMessage(from, recipient, title, content);
            await smtp.SendMailAsync(mail, ct);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "邮件发送失败: {Recipient}", recipient);
            throw;  // 抛出异常，让调用方决定是否重试
        }
    }
}
```

### 2.3 为什么注入 IServiceProvider 而不是 ISystemParamService？

```
SmtpChannelProvider 是 Singleton 生命周期
ISystemParamService 内部依赖 AppDbContext (Scoped)

如果直接注入 ISystemParamService，会导致：
  Singleton → Scoped 的 captive dependency（被捕获的依赖）

解决方案：
  注入 IServiceProvider，在每次 SendAsync 时手动创建 Scope
  或从 IServiceProvider 中延迟解析 ISystemParamService
```

## 三、配置步骤

### 步骤 1：在 SystemParam 表中添加 SMTP 配置

```sql
INSERT INTO SystemParams (Code, Value, Description)
VALUES ('smtp:default', '{
  "Host": "smtp.qq.com",
  "Port": 587,
  "User": "your-email@qq.com",
  "Password": "your-auth-code",
  "From": "PlatformBase <your-email@qq.com>"
}', 'SMTP 邮件服务器配置');
```

### 步骤 2：在 NotificationTemplate 表中配置邮件模板

```sql
INSERT INTO NotificationTemplates (Code, Name, TitleTemplate, BodyTemplate, Channel, IsEnabled)
VALUES ('welcome-email', '欢迎邮件', '欢迎加入 PlatformBase！',
        '亲爱的 {username}，感谢您注册。', 'email', 1);
```

### 步骤 3：发送邮件

```csharp
await _notificationService.SendAsync("welcome-email", userId, new Dictionary<string, string>
{
    ["username"] = "张三"
});
// 自动查找模板 → 变量替换 → 路由到 SmtpChannelProvider → 发送邮件
```

## 四、常见 SMTP 配置

| 邮箱 | Host | Port | 说明 |
|------|------|------|------|
| QQ邮箱 | smtp.qq.com | 587 | 需在 QQ 邮箱设置中开启 POP3/SMTP 服务，获取授权码 |
| 163邮箱 | smtp.163.com | 587 | 需开启 SMTP 服务，使用授权码 |
| Gmail | smtp.gmail.com | 587 | 需开启两步验证 + 应用专用密码 |
| 企业微信 | smtp.exmail.qq.com | 587 | 使用企业微信管理员设置的密码 |
| Outlook | smtp.office365.com | 587 | 使用 Microsoft 365 账号密码 |

## 五、异常处理策略

```
发送邮件:
  try {
    SmtpClient.SendMailAsync()
  }
  catch (Exception ex)
    → LogError("邮件发送失败: {Recipient}", recipient)
    → throw    （抛出异常，让 NotificationService 决定是否重试）

三种失败场景：
  1. SMTP 未配置 → LogWarning + return（静默跳过）
  2. JSON 格式错误 → LogError + return（配置问题，不重试）
  3. 网络/认证失败 → LogError + throw（可能重试）
```

│                      邮件通知架构                                 │

│                                                                 │

│         │                                                       │

│              │                                                  │

│  - Singleton Provider (无状态，线程安全)                         │
│  - 注入 IServiceProvider 延迟解析 ISystemParamService           │
