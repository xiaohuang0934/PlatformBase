# PlatformBase 全局操作日志过滤 — 手把手教学笔记

---

## 一、为什么需要操作日志？

任何企业系统都需要审计追踪：
- 谁在什么时候做了什么操作？
- 操作了什么数据？修改前后分别是什么？
- 操作是否成功？

传统做法是在每个 Controller 方法里手动记录，代码重复严重。

**解决方案：** 用 ActionFilter 机制，在 Controller 执行后自动捕获操作信息并异步写入数据库，业务代码零侵入。

---

## 二、实现逻辑总览

```
HTTP 请求到达
  │
  ▼
  Controller Action 执行
  │
  ▼
  OperationLogFilter.OnActionExecutionAsync
  │
  ├── 1. await next() 执行 Action
  ├── 2. 检查 [OperationLog] 标记 → 无则跳过
  ├── 3. 提取操作资源名（Resource = "controller.action"）
  ├── 4. 如果 CaptureArgs=true → 序列化请求参数为 JSON
  ├── 5. 合并 EF Core ChangeTracker 变更快照
  ├── 6. 构造 OperationLogEntry（含 User/IP/UA/成功标志）
  └── 7. Hangfire.BackgroundJob.Enqueue() 异步入队
         │
         ▼
  OperationLogWriterJob.WriteAsync() → 写入数据库
```

## 三、核心实现

### 3.1 OperationLogAttribute — 标记哪些接口需要记录

```csharp
[AttributeUsage(AttributeTargets.Class | AttributeTargets.Method, AllowMultiple = false)]
public class OperationLogAttribute : Attribute
{
    public string Action { get; set; }     // 操作类型：login/create/update/delete
    public string? Resource { get; set; }  // 自定义资源名（默认自动拼接 controller.action）
    public bool CaptureArgs { get; set; }  // 是否捕获请求参数（默认 false，保护敏感数据）
}
```

### 3.2 OperationLogFilter — 日志捕获与入队

```csharp
public class OperationLogFilter : IAsyncActionFilter
{
    public async Task OnActionExecutionAsync(ActionExecutingContext context, ActionExecutionDelegate next)
    {
        // ① 执行 Action
        var executed = await next();

        // ② 检查 [OperationLog] 标记
        var attr = context.ActionDescriptor.EndpointMetadata
            .OfType<OperationLogAttribute>().FirstOrDefault();
        if (attr == null) return;  // 无标记 → 跳过

        // ③ 确定资源名
        var resource = attr.Resource
            ?? $"{controller}.{action}";  // 如 "User.Create"

        // ④ 捕获请求参数
        string? detail = null;
        if (attr.CaptureArgs && context.ActionArguments.Count > 0)
        {
            // 过滤掉 CancellationToken 参数
            var serializableArgs = context.ActionArguments
                .Where(kv => kv.Key != "cancellationToken" && kv.Key != "ct")
                .ToDictionary(kv => kv.Key, kv => kv.Value);

            detail = JsonSerializer.Serialize(serializableArgs,
                new JsonSerializerOptions { MaxDepth = 2 });   // 深度限制 2 层
            if (detail.Length > 2000) detail = detail[..2000]; // 长度限制 2000
        }

        // ⑤ 合并 ChangeTracker 变更快照
        var changeSnapshot = _dbContext.ChangeSnapshot;
        if (!string.IsNullOrEmpty(changeSnapshot))
        {
            detail = detail != null
                ? $"{detail}\nChanges:{changeSnapshot}"
                : $"Changes:{changeSnapshot}";
            if (detail.Length > 4000) detail = detail[..4000]; // 合并后限制 4000
        }

        // ⑥ 构造日志条目
        var entry = new OperationLogEntry
        {
            UserId = _currentUser.UserId,
            Username = _currentUser.UserName ?? ExtractUsernameFromArgs(context, attr),
            Action = attr.Action,
            Resource = resource,
            Detail = detail,
            IpAddress = context.HttpContext.Connection.RemoteIpAddress?.ToString(),
            UserAgent = context.HttpContext.Request.Headers.UserAgent.ToString(),
            IsSuccess = executed.Exception == null && context.HttpContext.Response.StatusCode < 400
        };

        // ⑦ Hangfire 异步入队（不阻塞 HTTP 响应）
        BackgroundJob.Enqueue<OperationLogWriterJob>(job => job.WriteAsync(entry, CancellationToken.None));
    }
}
```

### 3.3 OperationLogWriterJob — 异步写入

```csharp
public class OperationLogWriterJob
{
    [AutomaticRetry(Attempts = 0)]  // 失败不重试（日志不是关键路径）
    public async Task WriteAsync(OperationLogEntry entry, CancellationToken ct)
    {
        await _logService.WriteAsync(entry, ct);
    }
}
```

### 3.4 匿名用户的用户名提取

```csharp
// 登录/刷新 Token 时用户尚未认证，从请求体中提取用户名
private static string? ExtractUsernameFromArgs(ActionExecutingContext context, OperationLogAttribute attr)
{
    if (attr.Action != "login" && attr.Action != "refresh") return null;

    foreach (var arg in context.ActionArguments.Values)
    {
        if (arg == null) continue;
        var prop = arg.GetType().GetProperty("Username");
        if (prop != null)
        {
            var val = prop.GetValue(arg) as string;
            if (!string.IsNullOrWhiteSpace(val)) return val;
        }
    }
    return null;
}
```

## 四、使用示例

```csharp
// 登录操作：记录操作 + 捕获参数（获取用户名）
[HttpPost("login")]
[OperationLog(Action = "login", CaptureArgs = true)]
public async Task<IActionResult> Login(LoginRequest request) { ... }

// 创建操作：记录资源 + 捕获参数 + 自动捕获数据变更
[HttpPost]
[OperationLog(Action = "create", Resource = "用户管理", CaptureArgs = true)]
public async Task<IActionResult> Create(CreateUserDto dto) { ... }

// 删除操作：不捕获参数（大对象或无意义）
[HttpDelete("{id}")]
[OperationLog(Action = "delete", Resource = "用户管理")]
public async Task<IActionResult> Delete(Guid id) { ... }
```

           │ await next()

│ OperationLogFilter       │────▶│ AppDbContext.         │

## 六、最佳实践速查卡

```
┌─────────────────────────────────────────────────────────────────┐
│              操作日志 黄金法则                                   │
├─────────────────────────────────────────────────────────────────┤
│  1. 用 [OperationLog] 标记要记录的接口，未标记的不记录            │
│  2. CaptureArgs 默认 false（保护密码等敏感数据）                  │
│  3. 请求参数序列化排除 CancellationToken（不可序列化）            │
│  4. MaxDepth=2 防止嵌套循环引用导致序列化崩溃                     │
│  5. 参数截断 2000 字符，变更快照合并后截断 4000 字符（保护 DB）   │
│  6. Hangfire 异步入队：不阻塞 HTTP 响应                          │
│  7. AutomaticRetry(0)：日志写入失败不重试（非关键路径）            │
│  8. ChangeSnapshot 自动捕获 EF Core 的 INSERT/UPDATE/DELETE       │
│  9. 全局注册为 ActionFilter：一次注册，所有 Controller 生效       │
│ 10. 登录/刷新时从请求体提取用户名（此时用户尚未认证）              │
└─────────────────────────────────────────────────────────────────┘
```
