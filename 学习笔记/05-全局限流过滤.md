# PlatformBase 全局限流过滤 — 手把手教学笔记

---

## 一、为什么需要 API 限流？

| 威胁 | 不设限流的后果 |
|------|---------------|
| 暴力破解 | 攻击者可无限次尝试密码 |
| 恶意爬取 | 爬虫无限请求，打满带宽和 CPU |
| 误操作循环 | Bug 导致死循环请求，拖垮服务器 |
| DDoS | 分布式请求淹没系统 |

**解决方案：** 基于 Redis 的滑动窗口算法，对每个 IP+端点 限制请求频率。

---

## 二、滑动窗口算法原理

### 不是"每分钟固定 60 次"，而是"过去 60 秒内最多 60 次"

```
时间轴 ──────────────────────────────────────────────────>
        │  窗口: [now - 60s, now]
        │  记录: ● ● ● ● ● ● ● (共 7 次) → limit=10 → 放行
        │
 60 秒前↓         当前 now
 ───────[●●● ● ● ● ●●]───
        已过期   │有效请求
        (被清理) │(参与计数)
```

### Redis 实现的 4 步原子操作

```
Step 1: ZREMRANGEBYSCORE key 0 (now-60s*1000)
         → 清理 60 秒前的时间戳（滑动窗口外）

Step 2: ZADD key now now
         → score=now, member=now（记录当前请求时间戳）

Step 3: EXPIRE key 61s
         → 设置 Key 过期，防止空间泄漏

Step 4: ZCARD key
         → 统计窗口内请求次数
         → count > limit → 拦截返回 200 + TooManyRequests
         → count ≤ limit → 放行
```

## 三、核心实现

### 3.1 RateLimitAttribute — 限流标记

```csharp
[AttributeUsage(AttributeTargets.Class | AttributeTargets.Method)]
public class RateLimitAttribute : Attribute
{
    public int Limit { get; set; } = 60;     // 窗口内最大请求数
    public double Seconds { get; set; } = 60; // 窗口长度（秒）
}
```

### 3.2 RateLimitFilter — 完整实现

```csharp
public class RateLimitFilter : IAsyncActionFilter
{
    private readonly IDatabase? _redis;  // 可能为 null（Redis 不可用时）

    public RateLimitFilter(IServiceProvider serviceProvider)
    {
        // 延迟获取：Redis 不可用时返回 null，不崩溃
        _redis = serviceProvider.GetService<IConnectionMultiplexer>()?.GetDatabase();
    }

    public async Task OnActionExecutionAsync(ActionExecutingContext context, ActionExecutionDelegate next)
    {
        // ① 检查标记
        var attr = context.ActionDescriptor.EndpointMetadata
            .OfType<RateLimitAttribute>().FirstOrDefault();

        if (attr == null || _redis == null)  // 无标记 或 Redis 不可用 → 跳过限流
        {
            await next();
            return;
        }

        // ② 构造 Key = "ratelimit:{ip}:{endpoint}"
        var ip = context.HttpContext.Connection.RemoteIpAddress?.ToString() ?? "unknown";
        var endpoint = context.HttpContext.Request.Path.ToString();
        var key = $"ratelimit:{ip}:{endpoint}";

        // ③ 计算时间窗口
        var now = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
        var windowStart = now - (long)attr.Seconds * 1000;

        try
        {
            // ④ 滑动窗口四步操作
            await _redis.SortedSetRemoveRangeByScoreAsync(key, 0, windowStart);  // 清理过期
            await _redis.SortedSetAddAsync(key, now, now);                       // 添加当前
            await _redis.KeyExpireAsync(key, TimeSpan.FromSeconds(attr.Seconds + 1)); // 过期时间

            // ⑤ 统计并判断
            var count = await _redis.SortedSetLengthAsync(key);
            if (count > attr.Limit)
            {
                // ⑥ 拦截：返回 200 + 错误 JSON
                context.Result = new ContentResult
                {
                    Content = JsonSerializer.Serialize(
                        ApiResult.Fail(ErrorCode.TooManyRequests, "请求过于频繁，请稍后重试"),
                        new JsonSerializerOptions { PropertyNamingPolicy = JsonNamingPolicy.CamelCase }),
                    ContentType = "application/json",
                    StatusCode = 200
                };
                return;
            }
        }
        catch
        {
            // Redis 异常 → 降级放行（保证核心业务可用）
        }

        await next();  // 未超限 → 放行
    }
}
```

## 四、使用示例

### 全局默认限流（所有接口）

```csharp
// Program.cs 中注册为全局过滤器
builder.Services.AddControllers(options =>
{
    options.Filters.Add<RateLimitFilter>();  // 全局生效
});
```

### 单个接口自定义限流

```csharp
// 登录接口：每分钟最多 5 次（防暴力破解）
[HttpPost("login")]
[RateLimit(Limit = 5, Seconds = 60)]
public async Task<IActionResult> Login(LoginRequest request) { ... }

// 注册接口：每分钟最多 3 次（防批量注册）
[HttpPost("register")]
[RateLimit(Limit = 3, Seconds = 60)]
public async Task<IActionResult> Register(RegisterRequest request) { ... }

// 查询接口：每分钟 120 次（高频接口宽松限制）
[HttpGet]
[RateLimit(Limit = 120, Seconds = 60)]
public async Task<IActionResult> GetUsers() { ... }
```

## 五、Key 设计

```
ratelimit:{IP}:{Path}

示例：
  ratelimit:192.168.1.100:/api/v1/auth/login    → 登录接口限流
  ratelimit:192.168.1.100:/api/v1/users          → 用户查询限流
  ratelimit:10.0.0.1:/api/v1/orders              → 订单接口限流

隔离粒度：同一 IP 的不同接口独立限流
```

## 六、Redis 数据结构

```
Key: "ratelimit:192.168.1.100:/api/v1/login"
Type: ZSet (Sorted Set)
TTL: 61 秒

内容（score=member=时间戳）:
┌──────────────────┬──────────────┐
│  Member (score)  │  含义        │
├──────────────────┼──────────────┤
│  1718280001000   │ 请求时间戳 1  │
│  1718280002500   │ 请求时间戳 2  │
│  1718280005000   │ 请求时间戳 3  │
│  ...             │  ...         │
└──────────────────┴──────────────┘
ZCARD → 3 → limit=60 → 放行
```

```
           │
  ┌────────┴────────┐

  └─────────────────┘
```

## 八、最佳实践速查卡

```
┌─────────────────────────────────────────────────────────────────┐
│              API 限流 黄金法则                                   │
├─────────────────────────────────────────────────────────────────┤
│  1. 使用 Redis ZSet 滑动窗口（非固定窗口）：精确到毫秒           │
│  2. score=member=时间戳：避免 ZADD 同一秒多次只保留一条          │
│  3. EXPIRE seconds+1：+1 防止窗口边界刚好过期时的竞态条件        │
│  4. Redis 不可用时降级放行：保证核心业务可用性                   │
│  5. try/catch 包裹 Redis 操作：网络超时/宕机不中断请求           │
│  6. 延迟获取 Redis 连接（不构造函数注入）：避免 DI 链崩溃        │
│  7. HTTP 状态码保持 200：统一 ApiResult 格式                     │
│  8. 登录接口 Limit=5（防暴力破解），查询接口 Limit=120（宽松）    │
│  9. Key = "ratelimit:{ip}:{endpoint}" 按 IP+路径 隔离            │
│ 10. 全局注册为 ActionFilter，标记即可生效，不标记不限制            │
└─────────────────────────────────────────────────────────────────┘
```
