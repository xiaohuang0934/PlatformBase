# PlatformBase 全局数据权限过滤 — 手把手教学笔记

---

## 一、什么是数据权限？

与"功能权限"不同，数据权限控制的是"能看到哪些数据"，而非"能否使用某个功能"。

| 类型 | 示例 | 实现方式 |
|------|------|---------|
| 功能权限 | 能不能访问"用户管理"页面 | `[Permission("users.view")]` |
| 数据权限 | 部门经理只能看自己部门的人 | `WHERE DepartmentId IN (...)` |
| 租户隔离 | 租户 A 看不到租户 B 的数据 | `WHERE TenantId = xxx` |

## 二、当前实现状态

> **当前为预留框架（PLACEHOLDER），尚未实现实际过滤逻辑。**

### 已有的基础设施

```csharp
// DataScopeAttribute — 标记哪些接口需要数据过滤
[AttributeUsage(AttributeTargets.Method)]
public class DataScopeAttribute : Attribute
{
    public string? BizType { get; set; }   // 业务类型（如 "order" / "user"）
}

// DataScopeFilter — 全局过滤器（当前为 PLACEHOLDER）
public class DataScopeFilter : IAsyncActionFilter
{
    private readonly ICurrentUserContext _currentUser;

    public async Task OnActionExecutionAsync(ActionExecutingContext context, ActionExecutionDelegate next)
    {
        // 检查 [DataScope] 标记
        var attr = context.ActionDescriptor.EndpointMetadata
            .OfType<DataScopeAttribute>().FirstOrDefault();
        if (attr == null) { await next(); return; }  // 无标记 → 跳过

        // 平台管理员不过滤
        // TODO: 基于 OrganizationUnit.Path 实现行级过滤
        await next();
    }
}
```

### 已有的多租户隔离

多租户隔离已在 `AppDbContext` 层面实现（`ApplyTenantFilters`），通过 `ICurrentUserContext.AccessibleTenantIds` 自动过滤租户数据。

```csharp
// AppDbContext 中的租户过滤（已实现）
modelBuilder.Entity<User>().HasQueryFilter(e =>
    AccessibleTenantIds.Contains(e.TenantId));  // 自动过滤租户数据
```

## 三、规划设计：完整的数据权限体系

### 数据模型

```
User ────属于──▶ OrganizationUnit (部门树)
                    │
                    └── Path (物化路径)
                        如: "/总部/研发部/后端组"
                        如: "/总部/市场部"
```

### 物化路径算法

```
张三 属于 "后端组" → Path = "/总部/研发部/后端组"

查询张三可看的数据时，用 LIKE 前缀匹配：
  SELECT * FROM Users
  WHERE EXISTS (
    SELECT 1 FROM OrganizationUnits
    WHERE OrganizationUnit.Id = Users.DepartmentId
      AND OrganizationUnit.Path LIKE '/总部/研发部/%'  -- 包含自己和所有子部门
  )
```

### 实现方式（两种方案可选）

#### 方案 A：HttpContext.Items 传递过滤条件

```csharp
// DataScopeFilter 中
var accessibleDeptIds = await GetAccessibleDeptIds(userId);
context.HttpContext.Items["DataScope:DeptIds"] = accessibleDeptIds;

// Repository 层读取
var deptIds = httpContextAccessor.HttpContext?.Items["DataScope:DeptIds"] as List<Guid>;
if (deptIds != null)
    query = query.Where(u => deptIds.Contains(u.DepartmentId));
```

#### 方案 B：Action 参数注入 Expression

```csharp
// DataScopeFilter 中
var filterExpression = BuildDataScopeFilter<Order>(userId);
context.ActionArguments["dataScopeFilter"] = filterExpression;

// Controller 中
public async Task<IActionResult> GetOrders(
    Expression<Func<Order, bool>> dataScopeFilter)
{
    var orders = await _repo.QueryAsync(dataScopeFilter);
}
```

## 五、使用示例（规划）

```csharp
// 标记接口需要部门级数据过滤
[HttpGet]
[DataScope(BizType = "order")]
public async Task<IActionResult> GetOrders()
{
    // 普通用户自动只能看自己部门的订单
    // 部门经理自动看自己及下级部门的订单
    // 平台管理员看全部
}

// 不同业务类型使用不同的过滤维度
[DataScope(BizType = "user")]
public async Task<IActionResult> GetUsers() { ... }

[DataScope(BizType = "report")]
public async Task<IActionResult> GetReports() { ... }
```

## 六、最佳实践速查卡

```
┌─────────────────────────────────────────────────────────────────┐
│            数据权限 黄金法则                                     │
├─────────────────────────────────────────────────────────────────┤
│  1. 租户隔离在 AppDbContext 层自动实现（已有）                   │
│  2. 部门级过滤在 DataScopeFilter 预留扩展点                     │
│  3. 平台管理员 IsSuperAdmin=true → 不过滤                        │
│  4. 物化路径 Path LIKE '/prefix/%' 实现递归子部门查询            │
│  5. 数据过滤条件应注入到 Repository 层（不在 Controller 中写）   │
│  6. BizType 区分不同业务的数据权限维度                           │
│  7. 全局注册为 ActionFilter，标记即可生效                        │
│  8. 数据权限 + 功能权限 两层独立控制                              │
│  9. HttpContext.Items 传递过滤条件（轻量，无需改接口签名）        │
│ 10. 过滤条件应在数据库层执行（IQueryable），不在内存中过滤       │
└─────────────────────────────────────────────────────────────────┘
```
