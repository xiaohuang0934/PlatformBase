## 一、为什么需要统一响应？

| 问题 | 传统模式 | 统一响应模式 |
|------|---------|-------------|
| 成功响应 | `{ "name": "张三" }` | `{ "code": 200, "data": { "name": "张三" }, "message": null }` |
| 失败响应 | `{ "error": "xxx" }` + HTTP 500 | `{ "code": 500, "data": null, "message": "xxx" }` + HTTP 200 |
| 前端处理 | 需判断 HTTP 状态码 + body 结构 | 统一判断 `code` 字段 |
| 异常处理 | 不同 Controller 格式不一 | 全局中间件统一格式 |

## 二、ApiResult 统一响应模型

### 2.1 核心定义

```csharp
public class ApiResult<T>
{
    public int Code { get; set; }        // 业务状态码（200=成功，其他=失败）
    public string? Message { get; set; }  // 提示信息
    public T? Data { get; set; }         // 业务数据
}

public class ApiResult : ApiResult<object>
{
    // 成功
    public static ApiResult Success(object? data = null, string? message = null)
        => new() { Code = 200, Data = data, Message = message };

    // 失败
    public static ApiResult Fail(int code, string message)
        => new() { Code = code, Message = message };

    // 泛型成功
    public static ApiResult<T> Success<T>(T data, string? message = null)
        => new() { Code = 200, Data = data, Message = message };

    // 泛型失败
    public static ApiResult<T> Fail<T>(int code, string message)
        => new() { Code = code, Message = message };
}
```

### 2.2 错误码定义

```csharp
public static class ErrorCode
{
    public const int Unauthorized = 401;       // 未认证
    public const int Forbidden = 403;          // 无权限
    public const int NotFound = 404;           // 资源不存在
    public const int Conflict = 409;           // 并发冲突
    public const int TooManyRequests = 429;    // 限流
    public const int InternalError = 500;      // 内部错误

    public const int InvalidInput = 1001;      // 参数校验失败
    public const int BusinessError = 1002;     // 业务规则错误
}
```

### 2.3 使用示例

```csharp
// Controller 中
[HttpGet("{id}")]
public async Task<ApiResult<UserDto>> GetUser(Guid id)
{
    var user = await _service.GetByIdAsync(id);
    if (user == null)
        return ApiResult.Fail<UserDto>(ErrorCode.NotFound, "用户不存在");

    return ApiResult.Success(user);
}

[HttpPost]
public async Task<ApiResult> Create(CreateUserDto dto)
{
    await _service.CreateAsync(dto);
    return ApiResult.Success(null, "创建成功");
}
```

## 三、GlobalExceptionMiddleware — 全局异常处理

### 3.1 完整实现

```csharp
public class GlobalExceptionMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<GlobalExceptionMiddleware> _logger;
    private readonly IWebHostEnvironment _env;

    public async Task InvokeAsync(HttpContext context)
    {
        try
        {
            await _next(context);  // 执行后续整个管道
        }
        // ① EF Core 并发冲突 → Warning（乐观锁正常保护）
        catch (DbUpdateConcurrencyException ex)
        {
            _logger.LogWarning(ex, "并发冲突：数据已被他人修改");
            await WriteErrorResponse(context, ErrorCode.Conflict,
                "数据已被他人修改，请刷新后重试");
        }
        // ② 业务异常 → Warning（预期内的业务规则失败）
        catch (BusinessException ex)
        {
            _logger.LogWarning(ex, "Business exception: {Message}", ex.Message);
            await WriteErrorResponse(context, ex.Code, ex.Message);
        }
        // ③ 未预期异常 → Error（Bug，需人工排查）
        catch (Exception ex)
        {
            _logger.LogError(ex, "Unhandled exception: {Message}", ex.Message);
            var message = _env.IsDevelopment()
                ? ex.ToString()      // 开发环境：返回完整堆栈
                : "Internal server error";  // 生产环境：隐藏实现细节
            await WriteErrorResponse(context, ErrorCode.InternalError, message);
        }
    }

    private static async Task WriteErrorResponse(HttpContext context, int code, string message)
    {
        context.Response.ContentType = "application/json";
        context.Response.StatusCode = (int)HttpStatusCode.OK;  // HTTP 200

        var result = ApiResult.Fail(code, message);
        var json = JsonSerializer.Serialize(result, new JsonSerializerOptions
        {
            PropertyNamingPolicy = JsonNamingPolicy.CamelCase
        });
        await context.Response.WriteAsync(json);
    }
}
```

### 3.2 JWT 认证失败的统一响应

```csharp
// 在 JwtBearerOptions 中配置
options.Events = new JwtBearerEvents
{
    // 未认证（无 Token / Token 无效 / 过期）
    OnChallenge = async context =>
    {
        context.HandleResponse();  // 阻止默认 401 响应
        context.Response.StatusCode = 200;
        var result = ApiResult.Fail(ErrorCode.Unauthorized, "认证失败，请重新登录");
        await context.Response.WriteAsync(JsonSerializer.Serialize(result, camelCase));
    },

    // 已认证但无权限（鉴权失败）
    OnForbidden = async context =>
    {
        context.Response.StatusCode = 200;
        var result = ApiResult.Fail(ErrorCode.Forbidden, "没有访问权限");
        await context.Response.WriteAsync(JsonSerializer.Serialize(result, camelCase));
    }
};
```

### 3.3 安全戳验证的 401 响应

```csharp
// StampValidationMiddleware
private static async Task WriteUnauthorizedResponse(HttpContext context, string message)
{
    context.Response.ContentType = "application/json";
    context.Response.StatusCode = 200;
    var result = ApiResult.Fail(ErrorCode.Unauthorized, message);
    await context.Response.WriteAsync(JsonSerializer.Serialize(result, camelCase));
}
```

### 3.4 FluentValidation 校验失败

```csharp
// 自动校验失败时，框架返回 400 + ValidationProblemDetails
// 可以通过配置覆盖为统一 ApiResult 格式
builder.Services.Configure<ApiBehaviorOptions>(options =>
{
    options.InvalidModelStateResponseFactory = context =>
    {
        var errors = context.ModelState
            .Where(e => e.Value.Errors.Count > 0)
            .ToDictionary(
                e => e.Key,
                e => e.Value.Errors.Select(x => x.ErrorMessage).First());

        var result = ApiResult.Fail(ErrorCode.InvalidInput,
            JsonSerializer.Serialize(errors));
        return new OkObjectResult(result);  // 同样是 200
    };
});
```

## 五、关键设计决策

### 为什么 HTTP 状态码恒为 200？

```
前端处理:
  if (response.code === 200) { handleSuccess(response.data); }
  else { handleError(response.code, response.message); }

优势:
  1. 前端只要一个 if 判断，不用处理 HTTP 状态码
  2. 避免浏览器对 401/403 的默认行为（如弹登录框）
  3. 4xx/5xx 在 CDN/代理层容易丢失 body
  4. 统一响应格式便于 AOP 拦截和日志记录
```

### 为什么开发环境返回完整堆栈？

```
生产环境:
  { "code": 500, "message": "Internal server error" }
  → 不暴露代码路径、数据库结构等敏感信息

开发环境:
  { "code": 500, "message": "System.NullReferenceException at PlatformBase.Host.Controllers.UserController.GetUser line 45 ..." }
  → 方便开发者快速定位问题
```

## 六、BusinessException 使用

```csharp
// 定义
public class BusinessException : Exception
{
    public int Code { get; }
    public BusinessException(int code, string message) : base(message)
    {
        Code = code;
    }
}

// 在 Service 中使用
public async Task UpdateUserAsync(Guid id, UpdateUserDto dto)
{
    var user = await _repo.GetByIdAsync(id);
    if (user == null)
        throw new BusinessException(ErrorCode.NotFound, "用户不存在");

    if (user.Email != dto.Email && await _repo.EmailExistsAsync(dto.Email))
        throw new BusinessException(ErrorCode.BusinessError, "邮箱已被占用");

    // ... 执行更新
}

// Controller 中无需处理，GlobalExceptionMiddleware 自动捕获
```

## 七、最佳实践速查卡

```
┌─────────────────────────────────────────────────────────────────┐
│         全局统一响应和异常处理 黄金法则                           │
├─────────────────────────────────────────────────────────────────┤
│  1. 所有接口返回 ApiResult，前端统一判断 code 字段               │
│  2. HTTP 状态码恒为 200（避免浏览器默认行为 + CDN 兼容）         │

│     (Error)                                                     │
│  5. 生产环境隐藏堆栈信息（"Internal server error"）              │
│  6. 开发环境返回完整堆栈（ex.ToString()）                        │
│  7. BusinessException 带自定义 Code，中间件自动捕获              │
│  8. JWT 认证/鉴权失败同样用 ApiResult 格式                      │
│  9. 统一使用 JsonNamingPolicy.CamelCase（驼峰命名）              │
│ 10. ApiResult 使用静态工厂方法（Success/Fail），禁止 new          │
└─────────────────────────────────────────────────────────────────┘
```
