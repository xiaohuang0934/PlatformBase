## 一、为什么需要重构？

### 原有问题

1. **权限粒度太粗**：Admin 角色拥有全部权限，租户管理员拿到 Admin 角色后，能看到租户管理、系统参数、定时任务等本不应看到的页面
2. **菜单无数据隔离**：所有用户看到的菜单由后端 `PermissionCode` 控制，但缺少用户类型层面的过滤
3. **租户部门数据泄露**：租户管理员创建用户时，部门选择器能加载到其他租户的部门数据
4. **无用户菜单关联**：菜单可见性完全依赖 RBAC 权限码，无法精确控制到用户级别

### 目标

```
平台管理员 (admin)     → 全部权限 + 全部菜单
租户管理员 (tenant)     → 租户内管理权限（无系统级管理）+ 租户菜单
普通用户 (tenant_user)  → 仅看到分配的菜单（UserMenu）
```

## 二、权限体系重构

### 2.1 角色拆分

**旧角色体系：**
| 角色 | 权限 |
|------|------|
| Admin | 全部权限 |
| Manager | 查看类权限 |
| User | `users.list` |

**新角色体系（DataSeeder.cs）：**
| 角色 | 说明 |
|------|------|
| Admin | 平台管理员专用，拥有全部 41 个权限 |
| TenantAdmin | 租户管理员专用，不含 `tenants.*` / `system-params.*` / `jobs.*` / `operation-logs.*` / `menus.*` |
| Manager | 业务管理员，仅 `users.list` / `roles.list` / `perms.list` |
| User | 最小权限（空） |

**种子数据变更：**
```csharp
// DataSeeder.cs:GetSeedRoles()
("TenantAdmin", "tenant_admin", "租户管理员 — 租户内全部权限...", true),

// 权限集（不含 menus.* / tenants.* / system-params.* 等）
("TenantAdmin", ["users.*", "roles.*", "datadict.*",
                 "tenant-params.*", "org-units.*",
                 "files.upload", "notifications.manage"]),
```

### 2.2 用户-角色分配变更

租户管理员（default_admin / zhijihui_admin）从 `Admin` 角色改为 `TenantAdmin` 角色：

```csharp
// DataSeeder.cs:SeedRolePermissionsAsync()
// 给所有 TenantAdmin 类型的用户自动分配 TenantAdmin 角色
var tenantAdmins = await uow.Repository<User>()
    .FindAsync(u => u.UserType == UserType.TenantAdmin);
if (roleMap.TryGetValue("TenantAdmin", out var tenantAdminRoleId))
{
    foreach (var ta in tenantAdmins)
        context.Set<UserRole>().Add(new UserRole { UserId = ta.Id, RoleId = tenantAdminRoleId });
}
```

### 2.3 RoleService 租户范围限制

租户管理员只能编辑/删除本租户的角色：

```csharp
// RoleService.cs:AssignPermissionsAsync()
if (_currentUser.UserType == UserType.TenantAdmin)
{
    if (role.TenantId != null && role.TenantId != _currentUser.TenantId)
        throw new BusinessException("只能编辑本租户的角色", ErrorCode.Forbidden);
}

// RoleService.cs:DeleteAsync()
if (_currentUser.UserType == UserType.TenantAdmin)
{
    if (entity.TenantId != null && entity.TenantId != _currentUser.TenantId)
        throw new BusinessException("只能删除本租户的角色", ErrorCode.Forbidden);
}
```

## 三、用户-菜单关联 (UserMenu)

### 3.1 为什么需要 UserMenu？

RBAC 权限码可以控制"用户能否访问某个页面"，但不能控制"用户在菜单栏能不能看到某个页面"。

典型的例子：
- `testuser` 没有 `tenants.list` 权限，所以看不到租户管理页面 — 这是 RBAC 做的
- 但 `testuser` 是普通用户，只想让他看到「文件管理」和「数据字典」两个菜单项 — 这需要 UserMenu 控制

### 3.2 实体与数据库配置

```csharp
// UserMenu.cs
public class UserMenu
{
    public Guid UserId { get; set; }
    public Guid MenuId { get; set; }
    public User User { get; set; } = null!;
    public Menu Menu { get; set; } = null!;
}
```

AppDbContext 配置：
```csharp
modelBuilder.Entity<UserMenu>(e =>
{
    e.HasKey(um => new { um.UserId, um.MenuId });
    e.HasOne(um => um.User).WithMany().HasForeignKey(um => um.UserId).OnDelete(DeleteBehavior.Cascade);
    e.HasOne(um => um.Menu).WithMany().HasForeignKey(um => um.MenuId).OnDelete(DeleteBehavior.Cascade);
});
```

### 3.3 菜单分配 API

| 端点 | 说明 |
|------|------|
| `GET /api/v1/users/{id}/menus` | 获取用户已分配的菜单 ID 列表 |
| `PUT /api/v1/users/{id}/menus` | 全量替换用户菜单关联 |

UserController 中的实现：
```csharp
[HttpPut("{id:guid}/menus")]
[Permission("users.edit")]
public async Task<ApiResult> AssignMenus(Guid id, IReadOnlyList<Guid> menuIds, CancellationToken ct)
{
    var user = await _service.GetByIdAsync(id, ct);
    if (user == null) return ApiResult.Fail(ErrorCode.UserNotFound, "用户不存在");
    await _menuService.AssignMenusToUserAsync(id, menuIds, ct);
    return ApiResult.Ok("菜单分配成功");
}
```

### 3.4 菜单树构建逻辑（核心）

MenuService.GetUserMenuTreeAsync 是全文最关键的逻辑，分三层过滤：

```csharp
public async Task<IReadOnlyList<MenuNode>> GetUserMenuTreeAsync(CancellationToken ct = default)
{
    var allMenus = await _uow.Repository<Menu>().FindAsync(m => m.IsEnabled, ct);

    // Layer 1：平台管理员看全部
    if (_currentUser.UserType == UserType.PlatformAdmin)
        return BuildTree(allMenus, null, null);

    // Layer 2：租户管理员 - 排除系统级菜单
    if (_currentUser.UserType == UserType.TenantAdmin)
    {
        var filteredMenus = allMenus
            .Where(m => !IsBannedForTenantUser(m.PermissionCode))
            .ToList();
        return BuildTree(filteredMenus, grantedSet, null);
    }

    // Layer 3：普通用户 - 权限匹配 + 菜单关联
    var visibleMenus = allMenus
        .Where(m => !IsBannedForTenantUser(m.PermissionCode))
        .Where(m => grantedSet.Contains(m.PermissionCode) || string.IsNullOrEmpty(m.PermissionCode))
        .Where(m => userMenuIds.Count == 0 || userMenuIds.Contains(m.Id))
        .ToList();
    return BuildTree(visibleMenus, grantedSet, userMenuIds);
}
```

**禁限权限前缀（租户用户/租户管理员均不可见）：**
```csharp
private static readonly HashSet<string> TenantUserBannedPermissions = new(StringComparer.OrdinalIgnoreCase)
{
    "tenants.",       // 租户管理
    "system-params.", // 系统参数
    "jobs.",          // 定时任务
    "operation-logs." // 操作日志
};
```

**空父菜单隐藏（BuildTree 最后一步）：**
```csharp
// 过滤掉没有子菜单的父级目录（Type=1）
return roots.Where(n => n.Type != 1 || n.Children.Count > 0).ToList();
```

## 四、系统参数 Inheritable 字段

### 4.1 设计思想

系统参数 vs 租户参数是「双表方案」：
- `SystemParam`：全局默认值
- `TenantParam`：租户覆盖值（不存在则 Fallback 到 SystemParam）

**问题：** 某些系统参数是平台级安全策略（如 `max_login_attempts`），不应该允许租户覆盖。于是增加 `Inheritable` 字段。

### 4.2 实体变更

```csharp
public class SystemParam : SoftDeleteEntity
{
    // ...原有字段...
    public bool Inheritable { get; set; } = true; // 新增
}
```

### 4.3 种子数据配置

```csharp
// 可继承（Inheritable=true）→ 租户可覆盖
new() { Code = "site_name",       Inheritable = true },  // 租户可自定义站点名称
new() { Code = "company_name",    Inheritable = true },  // 租户可自定义公司名称
new() { Code = "default_page_size", Inheritable = true }, // 通用分页配置
new() { Code = "max_export_rows", Inheritable = true },

// 不可继承（Inheritable=false）→ 仅平台级
new() { Code = "max_login_attempts",    Inheritable = false }, // 安全策略
new() { Code = "lockout_minutes",       Inheritable = false },
new() { Code = "access_token_lifetime",  Inheritable = false },
new() { Code = "super_admin_username",  Inheritable = false },
new() { Code = "smtp:default",          Inheritable = false }, // 邮件配置
```

### 4.4 TenantParamController 校验

创建租户参数覆盖值时，校验系统参数的 Inheritable 状态：

```csharp
var sysParam = await _uow.Repository<SystemParam>()
    .FirstOrDefaultAsync(p => p.Code == dto.Code && p.IsEnabled, ct);
if (sysParam == null)
    throw new BusinessException($"系统参数 '{dto.Code}' 不存在", ErrorCode.DataNotFound);
if (!sysParam.Inheritable)
    throw new BusinessException($"系统参数 '{dto.Code}' 不允许被租户覆盖", ErrorCode.Forbidden);
```

### 4.5 前端租户参数管理

新增 `DesktopTenantParamsList.vue` 页面，包含：
- **平台管理员**：租户下拉选择框 → 查看/编辑该租户的参数覆盖值
- **租户管理员**：自动绑定当前租户，只能操作自己租户的参数

菜单结构：
```
系统配置
  ├── 菜单管理     (menus.list)    → 仅平台管理员可见
  ├── 系统参数     (system-params) → 仅平台管理员可见
  ├── 租户参数     (tenant-params) → 租户管理员可见
  ├── 数据字典     (datadict.list) → 全部管理员可见
  └── 文件管理     (files.upload)  → 全部管理员可见
```

## 五、组织架构数据隔离

### 5.1 问题

创建用户时部门选择器 `OrgSelector` 调用 `GET /organization-units?mode=tree` 获取全量部门树。但此接口**没有按租户过滤**，租户管理员能看到所有租户的部门。

### 5.2 修复

**后端 OrganizationUnitService：**
```csharp
// GetFullTreeAsync - 租户用户只能看到自己租户的部门
public async Task<IReadOnlyList<OrgUnitNode>> GetFullTreeAsync(CancellationToken ct = default)
{
    var filterTenantId = _currentUser.UserType != UserType.PlatformAdmin
        ? _currentUser.TenantId : null;
    var all = await _uow.Repository<OrganizationUnit>()
        .FindAsync(o => o.IsEnabled && (filterTenantId == null || o.TenantId == filterTenantId), ct);
    return BuildTree(all);
}

// GetTreeAsync - 同样逻辑
var effectiveTenantId = _currentUser.UserType != UserType.PlatformAdmin
    ? _currentUser.TenantId : tenantId;
```

**前端 OrgSelector：**
```
新增 tenantId prop → 传给 API 参数
getOrgUnitTree(params?: { tenantId?: string })
```

### 5.3 组织架构控制器校验

```csharp
// 租户管理员只能查看本租户部门
if (_currentUser.UserType != UserType.PlatformAdmin && tenantId.HasValue
    && _currentUser.TenantId.HasValue && tenantId.Value != _currentUser.TenantId.Value)
    return ApiResult<IReadOnlyList<object>>.Fail(ErrorCode.Forbidden, "无权访问该租户的部门");
```

## 六、角色管理权限选择器

### 6.1 原状

创建/编辑角色的表单只有名称、编码、描述三个字段。权限分配需要创建角色后，再在列表行点击"分配权限"按钮。

### 6.2 改造后

新增权限选择器（按 `GroupName` 分组展示）：

```vue
<el-form-item label="权限">
  <div v-loading="permLoading" style="max-height:300px;overflow-y:auto;...">
    <div v-for="group in allPermGroups">
      <div>{{ group.group }}</div>
      <el-checkbox-group v-model="selectedPermCodes">
        <el-checkbox v-for="item in group.items" :label="item.code">
          {{ item.name }}
        </el-checkbox>
      </el-checkbox-group>
    </div>
  </div>
</el-form-item>
```

**权限选择范围：**
- **平台管理员**：可见全部权限
- **租户管理员**：只能看到自己拥有的权限（通过 `GET /auth/permissions` 过滤）

**提交流程：**
```typescript
// 创建：先创建角色 → 再分配权限
const res = await roleApi.createRole({...})
await roleApi.assignRolePermissions(newRole.id, selectedPermCodes.value)

// 编辑：更新角色 → 全量替换权限
await roleApi.updateRole(form.id, {...})
await roleApi.assignRolePermissions(form.id, selectedPermCodes.value)
```

## 七、前端优化

### 7.1 表格单元格省略

全局 CSS（`desktop.scss`）：
```scss
.el-table .cell {
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}
```

配合 `show-overflow-tooltip` 属性，长文本自动显示 `...`，鼠标悬停弹出完整内容。

### 7.2 操作按钮精简

移除列表行中的删除/禁用按钮，仅保留编辑：
- 用户管理：移除禁用、删除
- 角色管理：移除删除
- 权限管理：移除删除
- 租户管理：移除删除
- 系统参数：移除删除

删除操作统一通过工具栏"批量删除"处理。

### 7.3 分配菜单功能

从操作列移到工具栏：
```
[新增用户] [分配菜单] [批量启用] [批量禁用] [批量删除]
```
- 先选中一个用户（单选）→ 点击"分配菜单" → 树形选择器选择菜单项
- 创建用户时也可直接分配初始菜单（`CreateUserDto.MenuIds`）
